# ACP Goal mode: next prompt becomes objective

## Context

ACP currently advertises only `default` and optional `plan`; Goal lifecycle exists only in TUI and RPC hosts. Add wire-visible ACP mode id `goal`: selecting it without a stored goal arms the session, and the next prompt not successfully routed as a registered command becomes the persistent objective; a paused goal resumes on its next prompt while Goal remains selected. Goal continuation must stay inside the open `session/prompt` lifecycle merged in `e0420f1b7b`, so IntelliJ sees every continuation and Stop remains the escape. This slice adds Goal only; Vibe, guided-goal, Loop, and Tan ACP exposure remain separate work.

### 3. Add an ACP-specific Goal mode adapter

- Create `packages/coding-agent/src/modes/acp/acp-goal.ts` with `AcpGoalController`, a thin state adapter around `GoalHostController`. It owns only ACP semantics:
  - `selected`: transient ACP selection, set by the client; retained across interrupted/paused Goal state, cleared by explicit mode exit, terminal completion/drop, and process/session reattach.
  - `objectivePending`: transient arm set by selecting `goal` when no paused/active goal exists.
  - `modeSelected`: mirrors `selected` while armed, active, paused, or budget-limited; state mode `exiting` remains selected until its terminal `agent_end` journals completion.
  - `continuationPending`: forwards the shared controller probe.
  - `select()`: mark selected; no-op for active/exiting Goal; retain a paused Goal without resuming or starting a turn; otherwise arm the next objective.
  - `leave()`: clear selection and arm; call the shared pause path for any resumable active/budget-limited/paused Goal (pause is idempotent) so `goal_paused` persistence is preserved and `#exit` always restores the pre-goal tool set, including after Stop or reattach.
  - `prepareHostPrompt(text)`: when armed, reject empty text without clearing the arm, otherwise call `createForHostPrompt({ objective: text })`; when selected with paused Goal, call `resumeForHostPrompt()`; clear the arm only after successful creation and return which transition occurred.
  - `observe(event)`: forward first, then clear `selected` only after completion/drop leaves no resumable Goal; an interrupt-induced paused state keeps Goal selected.
  - Forward `stopForHostAbort`, `reconcile`, `settled`, `beginSessionChange`, and `endSessionChange` to the shared controller. Reconciliation always clears transient selection, so reopened active Goal becomes paused/default until explicitly selected.
- Make dynamic-command preflight share the exact current dispatch grammar. In `packages/coding-agent/src/extensibility/slash-commands.ts`, extract `parsePromptSlashCommand(text)` from `expandSlashCommand`: only literal ASCII space separates name/args, matching current extension/custom/file dispatch. Reuse it in `AgentSession.#tryExecuteExtensionCommand`, `#tryExecuteCustomCommand`, and `expandSlashCommand` instead of three copies. Add `AgentSession.isRegisteredPromptCommand(text): boolean`, using that parser and the authoritative live sources `extensionRunner.getCommand(name)`, `customCommands`, and `slashCommands`; it returns false for unknown slash text and does not execute or expand anything. Skill and handled builtin paths already return before Goal preparation. ACP calls this one predicate, so registered extension/custom/MCP/file commands leave the arm intact while unknown slash text consumes it. Prompt images accompany the first Goal user turn but are not part of persisted objective text.
- Do not persist `selected` or `objectivePending`: reopening reports `default`; only real Goal state is journaled by `GoalRuntime`.

- ACP continuation is enabled by default because selecting Goal is an explicit request for autonomous work; existing RPC remains opt-in. Users with explicit `goal.continuationModes` keep their configured list unchanged.
