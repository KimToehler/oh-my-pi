## Context
Colleagues should clone the fork, run one script, and get the same omp setup the owner uses: the binary, plus agents, rules, skills, the merge-gate extension, global instructions, and the onara router models. Until now that config lived only in `~/.omp/agent` on one machine and was moved between laptops by tarball. The repository is public on GitHub.

Owner decisions (2026-10-20):
- Commit the config to the public repo and remove private references (internal repo names, private paths, `Learned in:` and `## Evidence` lesson metadata). The router URL and the `onara/...` model ids stay.
- Install mode: managed copy plus manifest, from the same commit as the binary. Not symlinks.
- Personal settings: the team `AGENTS.md` ships without the user profile. `config.yml` and `models.yml` are seeded once and never overwritten.

## Approach
1. `team-config/agent/**` holds `AGENTS.md`, `agents/` (auditor, oracle), `rules/` (24), `skills/` (9, including `angular-developer`), and `extensions/` (`merge-gate.ts`, `lib/plan-file.ts`). Private references are removed from rule text and lesson metadata.
2. `team-config/seed/{config.yml,models.yml}` are the owner's files, with two changes. `apiKey` becomes the env-var name `ONARA_ROUTER_KEY`, which omp resolves from the process env or `<agentDir>/.env`. It was a `!zsh -c 'source ~/.zshenv …'` command. `contextFiles.extra: [AGENTS.local.md]` is added.
3. `scripts/install-team-config.ts` mirrors `team-config/agent/**` into `getAgentDir()` and records sha256 per file in `<agentDir>/.team-config-manifest.json`. A file that left the repo is removed. Content the installer did not write (a local edit, or a same-named file from before the first run) is copied or moved to `<agentDir>/backups/team-config-<timestamp>/` before it is replaced or removed. Seeds are copied with `COPYFILE_EXCL`. Files outside the manifest are never touched.
4. `scripts/deploy-local.sh` runs the installer from the deploy worktree, after the binary swap, unless `OMP_SKIP_TEAM_CONFIG=1`. It also prints a PATH hint.
5. `merge-gate.ts` resolves the validator from `import.meta.dir/../skills/review-work/scripts/validate-gate-record.mjs`, no longer from `~/.omp/agent/...`. `OMP_GATE_VALIDATOR` still overrides it. The extension test moved to `team-config/tests/` so it is not shipped.
6. `bun run test:team-config` runs the extension test, the validator test, and the installer test. `team-config/README.md` and a banner in the root `README.md` document setup.

## Merge gate

A wrong path, a wrong hash comparison, or a symlinked source could overwrite or delete user files without a backup, or write outside the agent dir. The seeded `models.yml` changes how the router key is resolved, so a mistake there leaks the key or sends requests unauthenticated. Shipped rules or skills could still carry private references into a public repo. Severity: high for the user's data and the key, medium for the rest.
- Mandatory class: auth-secrets-pii
- Whole-diff review: needed: 4 layers (deploy script, installer, shipped agent config, docs)
- Accepted residual risks: the 8 skills from oh-my-openagent are published under the Sustainable Use License (provenance noted in team-config/README.md; the owner decides on public redistribution). The seeded config ships the owner's `approvalMode: yolo`. Owner decisions 2026-10-21: the installer re-checks containment and destination state immediately before each step but does not pin paths to the objects it checked (Bun/Node have no `openat`/`O_NOFOLLOW` path APIs).
