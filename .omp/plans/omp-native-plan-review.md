# omp-native-plan-review - Work Plan

## TL;DR (For humans)

**What you'll get:** In plan mode, omp can have every plan proposal reviewed by a second model from a different model family before the plan reaches you. A rejected plan goes back to the planner with the reviewer's blockers. An approved or unreviewable plan reaches you as before, with a short status line. The feature is a setting and is off by default.

**Why this approach:** The review moves to the one place every plan proposal already passes through inside omp, after the plan file is located and before any approval screen opens. That place knows which model wrote the proposal, which file will be approved, and when the user presses Esc, so there is nothing left to guess. The three approval paths (terminal, editor integration, automatic plan-yolo) share one plan lookup instead of three copies.

**What it will NOT do:** It never blocks you from getting a plan: if the reviewer cannot run or cannot be trusted, the plan goes through with a warning. It does not change how you approve plans. It does not run unless you turn it on.

**Effort:** Large
**Risk:** Medium - the plan-approval hand-off is shared by three modes and a public SDK method changes shape.
**Decisions to sanity-check:** The reviewer is allowed to run even when the planner's subagent allow-list would forbid it (it is a host step, not a delegation). The reviewer counts as cross-family only when every model that answered is classified and differs from the planner's class. Two rejections per series, then the plan goes to you with the open blockers.
