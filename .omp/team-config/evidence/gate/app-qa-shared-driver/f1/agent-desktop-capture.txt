## Final report

The desktop app's chat field now holds exactly `qa f1 agent check`, checked by reading the field back through the QA driver.

- **Preflight:** the first run failed because port 8080 returned HTTP 404 instead of the backend. Rerun with `--port 8081`, every check passed and the backend reported `UP`.
- **Attach:** connected to the one desktop app process running from this worktree, pid 81605.
- **Before:** `find chat-input` found one field, enabled and empty (`textLength=0`).
- **Type:** `type chat-input "qa f1 agent check"` wrote 17 characters into the field.
- **Proof:** `find chat-input --equals "qa f1 agent check"` returned `count=1 enabled=true focused=true textLength=17 equals=true`. The field's text is exactly that string.
- **Session:** I disconnected the driver afterwards. The text is still in the field and was not sent.

I also tried to run Spectre's `spectre ps` directly, and a project rule on test automation with real accounts blocked it. Everything after that went through the QA driver only. Nothing was signed in or typed besides the test string. I took no screenshot or UI tree because the text match is the proof.
