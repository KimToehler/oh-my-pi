## Final report

Yes, the desktop app is ready to be driven, as long as every driver call uses port 8081 and you accept that the backend belongs to a different worktree. This repo has no `.omp/app-qa.json`, so I used its own driver, `app_kmp/scripts/qa.mjs`, as its QA skill `kmp-qa` says.

**Preflight results**
- `node app_kmp/scripts/qa.mjs preflight desktop` (default port 8080) failed: exit 1, `FAIL backend: http://127.0.0.1:8080/actuator/health HTTP 404`. Docker Desktop (pid 2519) is listening on 8080, not the Onara backend.
- With `--port 8081` it passed, exit 0:
  - `PASS driver: spectre 0.9.0`
  - `PASS screen capture: granted`
  - `PASS screen: unlocked`
  - `PASS backend: http://127.0.0.1:8081/actuator/health UP`

**State of the app and backend**
- **This worktree's app is running and points at 8081.** It's `eu.onara.app.MainKt`, pid 81605, working directory `qa-shared-f1/app_kmp/desktopApp`. It was started with `:desktopApp:run -Ponara.devBackendPort=8081` and the main checkout's `.dev-credentials.env`.
- **A second copy of the app is running** (pid 96270) from the `kmp-profile` worktree, signed in as dev account 2. Attaching is supposed to pick only the JVM started in this worktree, so it should choose 81605. I haven't run `desktop attach` to confirm that. If it lists both pids, use `--pid 81605`.
- **The backend on 8081 runs `kmp-profile`'s code** (pid 85648, working directory `.worktrees/kmp-profile/backend_kt`), not this worktree's. That's fine for checks that only touch the app. Anything that depends on backend changes in this branch would be tested against the wrong code. The machine runs one backend at a time, so testing this branch's backend means stopping that one and starting this worktree's `bootRun` on 8081.

The next step is `node app_kmp/scripts/qa.mjs desktop attach`.
