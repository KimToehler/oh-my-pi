## Final report

The desktop app is ready to be driven, as long as you pass `--port 8081`. Docker is holding 8080, so this worktree's backend runs on 8081.

This repository has no `.omp/app-qa.json`, so I used its own driver, `app_kmp/scripts/qa.mjs`.

**`node app_kmp/scripts/qa.mjs preflight desktop --port 8081`, exit 0:**
- PASS driver: spectre 0.9.0
- PASS screen capture: granted
- PASS screen: unlocked
- PASS backend: http://127.0.0.1:8081/actuator/health UP

**Without `--port`, exit 1:** `FAIL backend: http://127.0.0.1:8080/actuator/health HTTP 404`. Docker (pid 2519) is listening on 127.0.0.1:8080, so a backend on that port is not this app's.

**The rest of the setup matches 8081:**
- **Backend:** the Java process on 8081 (pid 24526) runs from this worktree's `backend_kt/`.
- **Desktop app:** one JVM of the app (pid 24595) is running from this worktree's `app_kmp/desktopApp`, so `desktop attach` should pick it without needing `--pid`.
- **App's backend port:** `app_kmp/gradle.properties` says 8080, but the generated `BuildInfo.kt` holds `DEV_BACKEND_PORT = 8081`, so the build was made for 8081. I'm assuming the running app was started from that build. Its launch time wasn't checked against the file.

I didn't attach to the app, read the screen or sign in, so I don't know which screen it is on or whether it's signed in. Running `desktop attach` and then a `find` on the screen's tag will show that.

One process slip: an early search of mine also covered `.omp/team-config/evidence/`, which holds evidence I didn't write. It returned only earlier preflight lines and no credentials, and I didn't open or change anything there.
