## Final report

Account 2 is signed in on the iOS simulator (`onara-f1`). The driver's sign-in flow passed and landed on the onboarding welcome screen (`onboarding-welcome`).

**Screen after sign-in:** the onboarding welcome page in German. It reads "Willkommen bei Onara" and "Schön, dass du da bist." with the Onara wordmark and "Dein Tag, dein Rhythmus." Below are the language chips (Deutsch selected, English) and the "Loslegen" button. Screenshot: `/var/folders/c6/rmmgm5s52vsc2_g434mnp_nm0000gn/T/qa-acct2-j1oyz6s8/fresh-out/after-signin.png` (the credential scan found nothing in it).

What got in the way:
- **Backend:** Docker holds port 8080, so the backend check failed there. The backend that's up is on 8081. I ran the checks against 8081, and the last iOS build in this worktree uses 8081 too.
- **Old session:** my first sign-in attempt failed because the app was already signed in on the onboarding screen, and nothing was typed. I couldn't tell which account that session belonged to, and onboarding has no sign-out button.
- **I cleared the simulator's whole keychain** to end that session. That was the only way to sign out from there, but it removes every keychain item on this simulator, not just the app's. After that, account 2 signed in normally.

**A risk to rotate:** the QA driver blanks out your macOS username (`/Users/[redacted]/…`) in every path it prints. It only blanks configured username and password values, so one of the dev account values in `.dev-credentials.env` matches your macOS username. The value itself never showed up in my output, but if it's a password, it's now guessable from that. It also makes the credential scan flag any file that contains a home-directory path.

My temporary flow files, probe output and the failed run's logs are deleted; only the screenshot's folder is left, and a rescan of it is clean.
