## F1 scenarios

**Setup.** Android emulator (API 34, Chrome) and iOS simulator (iPhone 16), debug builds pointed at the staging Keycloak and the staging orders API. Preconditions: the staging client is configured as in D3, "Save events" is on for user events, and a QA user has at least one order.
- `L` is the staging client's access-token lifespan, read from the Keycloak admin console and written into each file.
- Each file records the steps, the observation, the screenshots or recording paths, and the Keycloak user events with their timestamps.
- No password is written into evidence.

For `p` in `android` and `ios`:
- `p-first-sign-in.md`: fresh install shows the sign-in screen. Sign in → the order list shows the QA user's orders, and a `LOGIN` and a `CODE_TO_TOKEN` event exist. Force-quit and relaunch → the order list appears without the browser. Android only: `adb shell pm clear APP_ID`, then sign in again while Chrome still holds the Keycloak SSO session → the app receives the redirect and shows the order list.
- `p-forged-redirect.md`, on the sign-in screen, once with no attempt pending and once after tapping Sign in and backing out:
  - Android: `adb shell am start -a android.intent.action.VIEW -d 'APP_ID:/oauth2redirect?code=forged&state=forged&iss=<issuer>'`.
  - iOS: `xcrun simctl openurl booted 'APP_ID:/oauth2redirect?code=forged&state=forged'`.

  Expected: the app stays on the sign-in screen, and no `CODE_TO_TOKEN` event exists for that time. On iOS `openurl` reaches no handler.
- `p-refresh-before-expiry.md`: sign in at time `t0`; at `t0 + L + 10 s`, reload the order list → the orders load, a `REFRESH_TOKEN` event exists between `t0 + L - 60 s` and the reload, and no new `LOGIN` occurs.
- `p-rejected-refresh.md`: sign in at `t0`; in the admin console, user → Sessions → Sign out; at `t0 + L + 10 s`, reload the order list → the sign-in screen is shown and a `REFRESH_TOKEN_ERROR` event exists. Force-quit and relaunch → the sign-in screen is shown (stored tokens deleted).
- `p-log-scan.md`, after all scenarios on that platform:
  - Android: `adb logcat -d --uid=<uid>`, where `<uid>` is the `uid:` value printed by `adb shell cmd package list packages -U APP_ID`. This covers every process of the app since boot, including those before force-quits.
  - iOS: `xcrun simctl spawn booted log show --last 2h --info --debug --predicate 'process == "iosApp"'`.

  Count the lines containing `eyJ` (the prefix of Keycloak's JWT access and refresh tokens) and the lines containing `oauth2redirect?` (a logged redirect URI with its code). Expected: 0 for each.

`android-pkce-mismatch.md`: tap Sign in; in `chrome://inspect`, read the authorization request URL from the Custom Tab's Network panel; navigate the tab to the same URL with `code_challenge=E9Melhoa2OwvFrEMTJguCHaoeK1t8URWbuGJSstw-cM`; log in → the app shows the sign-in failure and a `CODE_TO_TOKEN_ERROR` event exists. Force-quit and relaunch → the sign-in screen is shown.
