# Gate

- **Mandatory class**: auth-secrets-pii
- **Risk tier**: product
- **Author's risk assessment**: The change delivers authentication against the company Keycloak and stores access and refresh tokens that grant access to customer orders, so the class is auth-secrets-pii. The tier is product because it ships to users. The worst outcomes are irreversible: a token sent to a foreign origin, a token readable at rest or in logs, or a session accepted from a forged or mismatched authorization response all disclose customer orders. A refresh race or a missed sign-out keeps a rejected session alive. The changed state machine (D4) also has concurrency risk; its class is subsumed here and its review is the same full review. Whole-diff review is needed because the change spans four independently testable layers: the Gradle build, the `app.auth` session and storage, the `app.http` API client, and the androidMain/iosMain platform stores and entry points.
- **Whole-diff review**: needed
- **Accepted residual risks**: If the platform store fails to delete the tokens after Keycloak rejects the refresh token and the process then dies, the next start restores the tokens. The access token stays usable at the API for at most its remaining lifetime (Keycloak access-token lifespan) until the next refresh is rejected again and signs the user out. In-process the session is signed out at once (design.md D4, Risks).
- **Out of scope for blocking**: Platform wiring in the follow-up change `oidc-app-integration`: Activity and redirect registration, URL schemes, Android backup rules, per-flavor build-config values, and order-list and sign-in UI. design.md "Platform contract" defines it, and findings about it belong to that change's own review. This change's obligations on that boundary (`AuthComponents`, fail-closed restore of backed-up ciphertext) stay in scope.
