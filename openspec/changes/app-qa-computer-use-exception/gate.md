# Gate

- **Mandatory class**: auth-secrets-pii
- **Depth**: risky (the mandatory class)
- **Risk tier**: product
- **Author's risk assessment**: The change relaxes a ban that sits next to the team's credential guardrail: it lets a session take window screenshots and accessibility reads of a host desktop on which dev accounts sign in to real identity-provider pages and password managers. A wrong boundary (an exception read as "any dialog", an app with accounts treated as exempt, a display or other-app capture, a rule that does not load before a `computer` call) lands a screenshot or an element value holding a real dev password in a transcript that cannot be scrubbed; that consequence is why the class is auth-secrets-pii and not `none`, although the change handles no credential itself and edits only instruction text, rule triggers and what omp's eval bridge records for a failed `computer` call (design D22(c)). Product tier: the skill and rule govern every agent session that drives an app with real accounts.
- **Whole-diff review**: not needed (whole-diff surface reviewed in F2)
- **Accepted residual risks**: A sheet or overlay the target app itself shows inside its own window is captured with it; the exception applies only to apps whose configuration has no `credentials` section, so such an app has no sign-in surface, but an app that signs in through another route is not detected. A window-scoped capture holding only the target window's content rests on `crates/pi-natives/src/desktop/macos/capture/helper.m:68` and `:71` and is probed by the QA lane's `ce-overlap` on one macOS version, not guaranteed for every window server state. The host window of a simulator or emulator is never captured or read, and a screen reader is never read by a session (a human step, design D20). The rule and skill are guidance, not enforcement, as for the driver change (`team-config/README.md:343`). Whether a `computer` call matches the new rule condition depends on the call's text. The measured token costs are one pass on one app (2026-11-12). A code search by a session that is not doing QA (it never reads the skill) can reach evidence folders, with ignore rules off or, where a repository tracks its evidence, by default; kept by the user, Tim, 2026-11-12: "a code search outside QA is outside the QA skill's reach" (design D10). A QA session's search with ignore rules on over the whole worktree, run before it has loaded either of the rules `ui-automation-credentials` and `app-qa-evidence` or read the skill, still reaches evidence a repository tracks (weaver tracks `.omp/team-config/evidence/`); kept by the user, Tim, 2026-11-13: "guidance cannot stop a search it has not loaded for; closing it needs a tool change, which is a separate change" (design D14).
- **Out of scope for blocking**: the `computer` prelude itself and its settings or defaults, except its fixed failure status text (`statusError`) and the eval status a failed `computer` call records (design D22(c)), which stay in scope (`computer.enabled` stays `false` and `computer.backgroundFallback` stays `takeover` in code); `qa.mjs` and its tests; onara's and weaver's repository QA skills and any app-specific VoiceOver procedure; the DeviceHub input skill; Android TalkBack tooling (a human step, not a surface of this change); the unchanged sections of `ui-automation-credentials` and `team-config/agent/AGENTS.md:20`. Findings there become follow-ups.
