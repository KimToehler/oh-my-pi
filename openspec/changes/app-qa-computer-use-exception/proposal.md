# Proposal

## Why

The team skill `app-qa-drivers` forbids every OS-level GUI call (`team-config/agent/skills/app-qa-drivers/SKILL.md:84`), and the spec requirement "The team skill routes a fresh agent to the shared driver" (`openspec/specs/app-qa-driver/spec.md:254`) makes any such call by a fresh agent a failure. The tag driver (`qa.mjs`) cannot reach a screen reader, a dialog the app raises or a simulator host menu, so a dialog or host-menu check has no sanctioned tool today, and neither has a VoiceOver pass. omp now ships a `computer` eval prelude (setting `computer.enabled`, `packages/coding-agent/src/tools/settings.ts:635`) with window screenshots, accessibility trees and native input. A real pass on 2026-11-12 used it for VoiceOver on weaver's desktop app and found that Compose Desktop exposes containers as `AXUnknown` and the engine views are opaque to VoiceOver, findings no tag driver can produce (weaver, branch `plan/m5-app-design-workspace`, commit `2ef16890`, `.omp/team-config/evidence/gate/m5-app-design-workspace/f1/voiceover-human/README.md`). That pass cost about 40-50k tokens (a window screenshot about 1,400, an 86-node tree about 3,000, an unfiltered `observe()` about 5,000; a driver tag lookup a few dozen), so the exception has to be narrow and economical. The outcome of the user's decision of 2026-11-13 (design D20): VoiceOver stays a human step. The exception that motivated the 2026-11-12 pass covers app dialogs and host menus only, because no `computer` call ties a capture to the focus at capture time, so no rule can keep another app's announcement out of a capture of the caption panel.

## What Changes

- The team skill allows omp's `computer` prelude for exactly two kinds of surface the driver cannot reach: dialogs the app under test raises, and simulator or emulator host menus (for example Xcode 27 DeviceHub's Device > Accessibility menu). A screen-reader check (VoiceOver, its caption panel, TalkBack) is a human step: the session may bring the app to the screen through the driver, makes no `computer` call for the screen reader and reports which element to check and which announcement to expect (design D20). Everything a test tag reaches keeps going through the driver; computer use never replaces it.
- Only the `computer` prelude; raw `osascript`, System Events, CGEvent, `screencapture` and custom Swift helpers stay forbidden for every surface.
- Only for an app whose `.omp/app-qa.json` configures no `credentials`: an app with a sign-in surface gets no computer use at all. Only one resolved target window is captured or read (the dialog the app under test raised, identified as the one window of the app whose accessibility subrole says dialog); the simulator or emulator host app is reached through its window's menu only (`win.menu.items`, `win.menu.select`) and its window is never captured or read, because the device is shared with other repositories' flows; no display or desktop capture, no other app's window. The rule `ui-automation-credentials` keeps every existing line unchanged; it gains a trigger so it loads before a `computer` call and one pointer bullet. Dialogs of other processes are out of scope.
- A new rule `app-qa-evidence` (split from `ui-automation-credentials`, design D18) carries the folder and search clauses of the skill's section "Evidence you did not write", loads on a `mkdir` naming an evidence path and on a search with ignore rules off, before the call runs, because F1 sessions acted on evidence folders before reading the skill (design D12, D14) and a rule triggers once per session, so the credentials rule spent on a skill read could not interrupt them; rule and skill exclude `**/evidence/**` and `**/*-evidence/**` from any search over the whole worktree (design D13). The new rule and the repeat paragraph of `ui-automation-credentials` apply during app QA, or in a repository with `.omp/app-qa.json`, so a non-QA session is not bound by them; the `computer` condition of the credentials rule is `\bcomputer\.[A-Za-z]` only.
- Economy rules: capture the target window only, zoomed or silent captures combined into one grid; print only the accessibility lines the check needs; no whole-tree dump, no unfiltered observation, no desktop capture.
- Computer use needs omp's setting `computer.backgroundFallback: refuse` as well as `computer.enabled`: a `computer` outcome that ran in takeover stops the session and is reported. The session never calls `computer.apps.open`, resolves a window only from an app-filtered listing (design D19, D20) and takes the driver's lock around a host-menu step.
- Evidence a session keeps states that computer use was used and for which surface.
- The skill's section "Proving a QA instruction change" gains the proof for this exception: fresh sessions in both directions, with the same capture-and-scan discipline.
- The credential rule `ui-automation-credentials` loads before any `computer` helper call and points such a call, in a repository with `.omp/app-qa.json`, to the skill and its credentials and one-window limits; the skill's description routes any computer use there, so a request not phrased as a QA check still reaches the limits.
- The skill's section "Evidence you did not write" also covers evidence the task does not name: a search never covers an evidence folder, `.omp/` or `.omo/` as a whole, or runs with ignore rules off (F1 found a search that returned another change's gate evidence); the session creates its own output folder with `mkdir` without `-p` in its own step and never passes an `--out` below a folder it did not create.
- **Not in this change** (assumptions, recorded): `computer.enabled` keeps its default `false` and `computer.backgroundFallback` its default `takeover` in code; enabling it stays a per-user setting (Tim's `~/.omp/agent/config.yml` already has it), so a session without the prelude reports it missing. No change to `qa.mjs`, the prelude, onara's or weaver's repository QA skills, or the DeviceHub input skill.

## Impact

- Changed: `team-config/agent/skills/app-qa-drivers/SKILL.md` (the "No OS-level GUI scripting" bullet becomes the exception, one new section, the intro line, the failed-preflight bullet, the evidence section and the proof section), `team-config/agent/rules/ui-automation-credentials.md` (two conditions added to the five existing ones, description, one bullet and one guarded paragraph) and the new `team-config/agent/rules/app-qa-evidence.md` (two conditions, the folder and search clauses). `team-config/agent/AGENTS.md:20` and `team-config/README.md` stay unchanged.
- Deployment: `scripts/deploy-local.sh` already mirrors `team-config/agent/**`; no new install.
- Consumers: every agent session in a repository using the shared driver; effective only where `computer.enabled` is true.
- Credentials: no credential is handled by the change, but it relaxes a ban next to the credential guardrail; see gate.md.
