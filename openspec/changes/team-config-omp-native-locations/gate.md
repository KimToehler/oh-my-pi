# Gate

- **Mandatory class**: schema-migration
- **Risk tier**: product
- **Author's risk assessment**: The change rewrites the persisted contract of the merge gate: the record id (`omo.merge-gate/v2` → `team-config.merge-gate/v3`), a newly required `whole_diff.report_sha256` that also admits the bound F3 report to the post-review commit exemption, and the on-disk ledger and delta locations, all without migration, for every machine and repository that deploys team-config (this repository and onara). The merge gate is the process boundary that keeps unreviewed code out of `main`. The worst realistic failure is fail-open: a stop hook or validator that still lets a record under a retired id back a merge claim, including a merged historical v2 record through the settled shortcut, an exemption that lets a file other than the bound report change after `reviewed_sha`, or a validation that passes on working-tree bytes the commit does not hold. A silent merge of unreviewed work is the consequence. The fail-closed direction is a valid v3 record refused because the extension's id drifted from the scripts' (D4), or a running gate losing its ledger state; both block work but are visible. A persisted-format cutover with no migration is `schema-migration`, which rules out `internal-tooling`, so the tier is `product`.
- **Whole-diff review**: needed
- **Accepted residual risks**: Plans still under `.omo/plans` (this repository until P5b, onara) lose rule-glob injection until they are moved. A gate opened on the old ledger after the Migration Plan inventory, and not closed before the deploy, restarts with a fresh baseline. A user who keeps `plan.autosaveDir: .omo/plans` after the notice keeps saving plans there. A new v3 record or trailer written outside `.omp/team-config/evidence/` is accepted (decided by Tim, 2026-10-23: the location stays free; the id alone retires every old record, and its bytes stay bound by `trailer_sha256` and the tracked-file checks). A record placed in a directory whose loader picks up any new `.md` file can exempt one new Markdown file there that opens with `INTEGRATION-REVIEW-REPORT-v1` (decided by Tim, 2026-10-23: the report gets the trailer-style format gate of design.md D11, and the record author, who could equally forge a trailer, chooses the record directory).
- **Out of scope for blocking**: P5b (moving this repository's `.omo/plans` and `.omo/evidence`, and retiring the root `.gitignore` `.omo` block); P5c (`skills/coding-agent-sessions` OmO platform, local OmO state deletion); the `oh-my-openagent` provenance notes in `team-config/README.md`; onara's own rules, `.gitignore` and records; omp core under `packages/`; the historical text allowlisted in design.md D7.
