```
5. **Route the change's follow-ups**

   Follow-ups are findings a later change should pick up. This step only reads the gate record and the files it pins; it never edits, moves or annotates any of them.

   Collect from the change's gate record (`.omp/team-config/evidence/gate/<change-name>.json`, or the record path the repository's `review-work` convention names):
   - every `downgrades` entry with `disposition: follow-up`;
   - every non-blocking finding in the replies the record binds: each `verdicts[].trailer_artifact`, and the whole-diff report when `whole_diff` names one. A non-blocking finding is a note, or a finding in an area the change's `gate.md` names under `Out of scope for blocking`. Replies the record does not bind (earlier waves, retried dispatches) are not read.

   No gate record: collect nothing, and say so in the summary.

   Write each item as one bullet: the finding and its consequence, its location as `PATH:LINE` (or the area when no line applies), then `Source:` followed by the change name in backticks, the wave, and the reviewer or blocker id. Skip an item whose location and source already appear in the destination.

   Destination: the Markdown documents outside `openspec/` that `proposal.md` names by repository path. When exactly one of them has a `## Follow-ups` section, append the items there without asking. Otherwise, and only when items were collected, ask the user once, offering each named document and skip; a chosen document without the section gains `## Follow-ups` at its end. Never write to a document the proposal does not name.

   When `proposal.md` has a `## Follow-ups taken` section, delete each bullet listed there from the document that holds it. Keep every listed bullet you cannot find verbatim for the summary.

   Routing never blocks the archive: continue with the next step whatever was written or skipped.
```
