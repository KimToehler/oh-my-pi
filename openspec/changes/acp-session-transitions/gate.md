# Gate

- **Mandatory class**: wire-contract-api
- **Risk tier**: product
- **Author's risk assessment**: The change alters behaviour that independently released consumers rely on: ACP clients (Zed, JetBrains Air) see a deleted session closed and get an unknown-session error, and third-party extensions get `{ cancelled: true }` from `ctx.newSession`/`ctx.branch`/`ctx.switchSession` under ACP. Breakage modes: the close after `/session delete` cancels or swallows the confirming prompt response, or closes a session whose delete failed (user loses a live session); the store change stops persisting a session that was not deleted (silent transcript loss in every mode, the worst outcome) or breaks TUI `/session delete` → new session; the refusal leaks into TUI/RPC and breaks extension workflows there. All reach users' stored transcripts, so the tier is product; the ACP wire and the extension API are externally consumed contracts, so the class is wire-contract-api.
- **Whole-diff review**: needed
- **Accepted residual risks**: Extensions that call `ctx.newSession`, `ctx.branch` or `ctx.switchSession` under ACP lose that capability until a session-replacement notification exists (user decision 2026-10-24, option 3); an ACP client is not told that its session was closed after `/session delete` until it sends the next request, because ACP has no agent-initiated close message.
- **Out of scope for blocking**: TUI-only and RPC-only presentation of `/session delete` (only file recreation is in scope there); the other open items of `.omp/plans/ACP_TUI_PARITY_BACKLOG.md`; ACP `session/load` or `session/fork` of sessions deleted by other processes.
