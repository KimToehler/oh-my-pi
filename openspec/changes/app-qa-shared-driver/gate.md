# Gate

- **Mandatory class**: auth-secrets-pii
- **Depth**: risky (the mandatory class; the change also moves the evidence scan that review-work's QA rows in app repositories rely on)
- **Risk tier**: product
- **Author's risk assessment**: The delivered driver reads real dev passwords of a remote identity provider (onara's Keycloak realm `onara`) from the main checkout's gitignored credentials file and hands them to Maestro, which types them into the real SSO page; that is a real credential crossing a real trust boundary, the reason onara's `kmp-qa-drivers` was `auth-secrets-pii`. The change rewrites where those values come from (configured keys instead of a key pattern, a file found from the working directory instead of the script's directory), so a wrong key list, a wrong root or a lenient configuration parser would leave a value unredacted in console output, a kept Maestro file or committed evidence, or hand the wrong account to a flow. The new no-credentials mode must not let a value exported in the caller's shell reach Maestro unredacted. A broken scan would pass leaking evidence in every repository that uses the driver. The host-wide lock now spans repositories; a wrong lock path would let two repositories' flows drive one device at once. The skill change routes every agent's app QA, so a wrong command or path sends agents back to hand-driving or to a missing script.
- **Whole-diff review**: not needed (whole-diff surface reviewed in F2)
- **Accepted residual risks**: Spectre is pre-1.0 (v0.9.0) with an experimental attach API; preflight admits only 0.9.0 from the sha256-pinned asset. Flow runs on one host are serialized by one lock, and a stale lock is removed by hand. During a run, Maestro's files in the owner-only run root hold the typed values until the sweep; a SIGKILL of the driver leaves them there until the OS clears the temporary directory. The byte scan cannot read screenshot pixels: a custom flow that screenshots the SSO page before its sign-in subflow returns breaks the skill's rule, and such an image would reach the output directory. Until onara's cutover change merges, onara's own driver uses `${TMPDIR}/onara-qa/flow.lock` and the shared driver `${TMPDIR}/app-qa/flow.lock`, so the two exclude each other only through the unlocked-Maestro-run check. A teammate who has not redeployed team config runs the older driver, which refuses a newer schema id but not an older driver's missing fix.
- **Out of scope for blocking**: onara's cutover (its configuration file, deleting `app_kmp/scripts/qa.mjs`, the onboarding runner's lock path, its repository skill and rule) and weaver's adoption (its configuration, Android test tags as resource ids, its app QA skill), each its own change in its own repository; sign-in subflows and identity-provider page selectors (app repositories); CI execution of flows and physical devices; non-macOS hosts; the team rule `ui-automation-credentials` (unchanged, only relied on). Findings there become follow-ups.
