# Gate

- **Mandatory class**: concurrency-state
- **Risk tier**: product
- **Author's risk assessment**: The change decides which blockers on a classified change may stay unfixed in every review lane. Too broad, a defect in delivered auth, migration, wire or state behaviour is accepted under a "verification" label and ships; too narrow, nothing improves. The threshold, every other exclusion and the validator are unchanged, and the text is revertible. Product tier because it changes how product work is gated. Class `concurrency-state` because it changes the guard of an existing review-flow transition (which blockers reach the Accept ask instead of the fix loop), as the `change-verification` spec classifies a changed transition of an existing review flow; both F2 reviewers run.
- **Whole-diff review**: not needed (three instruction texts that state one rule, its README description and two spec deltas; no executable code, no independently testable module or runtime layer)
- **Accepted residual risks**: Whether a blocker concerns only verification is the orchestrator's judgement from the blocker's stated consequence, shown to the user in the approach question; F1 shows the rule on fixtures, not a compliance rate. No reduction in review rounds is claimed.
- **Out of scope for blocking**: validator or script enforcement of the delivered-change/verification assignment; making blockers about F1 evidence the validator binds acceptable at F2 or F3 (the audit-trail exclusion keeps them excluded, and this change leaves that unchanged); the threshold, the other exclusions, coverage, Split and the approach-question trigger, which this change leaves as they are.
