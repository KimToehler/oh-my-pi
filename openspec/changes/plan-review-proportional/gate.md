# Gate

- **Mandatory class**: concurrency-state
- **Depth**: risky (Mandatory class concurrency-state; the change also alters the plan-review gate and `--reviewed`)
- **Risk tier**: product
- **Author's risk assessment**: The change rewrites the transitions of the existing plan-review flow (rounds, verdict, fix loop, user asks, apply authorization), so it keeps the class of a changed state machine, and it changes how every product change is gated before apply, so it is product. What can break: a plan with a real defect reaches apply because one or two reviewers missed it or the verifier refuted it (caught later by F2/F3, or shipped); a security finding dropped without the user; the loop dispatching past its budget or asking at every round; a model pin that no longer resolves stopping every review. The damage is rework or a missed defect in reviewed work; the change itself handles no credential, data or irreversible state, and F1, F2, F3 and the gate record stay unchanged behind it.
- **Whole-diff review**: not needed (three independently testable parts sharing one record contract: the schema review instruction with its templates, the `blocker-verifier` agent, and the validator's depth check with its tests; the `SKILL.md` and README edits only remove plan-review references)
- **Accepted residual risks**: The recall of the new loop against the old three-lens loop is not measured by this change; it is a follow-up on the existing corpus (`runs/evo-deleg/plan-review-experiment.json`, review-pilot ledgers), and a lower recall shows up only as more F2/F3 findings meanwhile. The verifier's severity rubric restates the `plan-reviewer` blocking threshold in its own prompt and can drift from it, because `plan-reviewer.md` is upstream code this change does not edit. The judgement limb of the depth predicate (a class-`none` change that alters a review, gate or release mechanism) is enforced by the instruction, the reviewers and F1, not by `validate-openspec-change.mjs`, which checks only the class limb.
- **Out of scope for blocking**: the `Blocker disposition` rules as applied to F2, F2 delta reviews and F3, and wording in `review-blocker-disposition` requirements this change does not modify; the bundled `plan-reviewer` prompt; the routing of small changes to plan mode in the `openspec` skill; the corpus measurement of the new loop.
