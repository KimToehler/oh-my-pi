## Blockers

### Correctness (StopCorrectness5)

1. **Correctness: F2 insisted-acceptance record vs. restricted downgrade rules (design D5, review-blocker-disposition spec, tasks 1.1)** — The plan requires an explicit user request to accept a non-eligible, uncovered F2 blocker to be recorded in the `downgrades` entry with the user's reason and the blocker's consequence. The same plan restricts every `rule` value the validator accepts. `below-threshold` is allowed only for eligible blockers. `accepted-residual` and `out-of-scope` are allowed only for covered blockers. `frozen` exists only for a user freeze at a convergence STOP, and the plan does not extend it. An insisted acceptance at an ordinary Phase 4 override, with no STOP, is neither eligible nor covered, so every legal rule value is forbidden by the instruction. The orchestrator must write a rule that is false by the plan's own definition, or the instruction contradicts itself. The same gap applies to a freeze-insisted blocker that is neither eligible nor covered. The validator (validate-gate-record.mjs:769, 789) accepts only those four values, and no rule value means 'user-insisted'. Evidence: design.md D5: "`below-threshold` is used only for eligible blockers, `accepted-residual` and `out-of-scope` only for covered ones". Spec 'The user's explicit acceptance is recorded', scenario 'User insists on accepting': "records it in that path's existing record (`gate.md` Override, the `downgrades` entry, ...)". Task 1.1 row `delta-accept-insisted` covers only delta, with no F2 insisted row. validate-gate-record.mjs:769: DOWNGRADE_RULES = {below-threshold, accepted-residual, out-of-scope, frozen}. review-work/SKILL.md:357 defines `frozen` as 'the user chose freeze at a convergence STOP'. Change: Decide, in design D5 and spec 1.1, which existing `rule` value carries an insisted acceptance on the F2 Phase 4 override outside a STOP. The choice must not be a false statement about eligibility or coverage. For example, state that the rule value records the user's chosen path and that the user's reason and the stated consequence go in `reason`, and widen the 'only for' limits accordingly. Alternatively, forbid insisted acceptance on the F2 override and keep only the freeze, delta and plan paths. Then add an F2 insisted row (`f2-override-insisted` → `user-accept-recorded`) to the replay set so the Verify matrix covers it.

### Verification (StopVerification5)

1. **Quality and verification — tasks 1.1–1.3 and F1** — The Verify commands accept an empty instruction quote as if it were bound to the edited file and evidence artifact. Evidence: tasks.md:5 requires each replay to record the deciding instruction sentence. The commands at tasks.md:9–11 and 17 only test `includes(n(x.sentence))`; when `x.sentence` is an empty string, both inclusion checks succeed for any file and artifact. An ordinary incomplete matrix entry with an empty sentence can therefore pass, including at final F1, without identifying an instruction that supports its decision. gate.md:7 accepts that the checker cannot prove entailment, but says it binds the quoted sentence; this failure is the absence of a bound sentence, not the accepted entailment limitation. The resulting misleading QA evidence is reversible before release but is part of the bound audit trail. Change: Require a non-empty, non-whitespace sentence before both inclusion checks, and include a control showing that an empty sentence makes each relevant Verify command fail.

### Checks (StopChecks5)

1. **CHECK 7 — One authoritative disposition definition** — Plan review is instructed to read the default agent directory’s policy even when the active session uses a profile or custom agent directory. The policy governing plan review can therefore differ from the policy used by F2 and F3, or be absent altogether. Evidence: design.md:19 and tasks.md:10 require the schema to reference `~/.omp/agent/skills/review-work/SKILL.md`; design.md:65 separately identifies profile and custom `PI_CODING_AGENT_DIR` installations. The installer writes to the resolved agent directory (`scripts/install-team-config.ts:625-628`), and the runtime supports overriding it (`packages/coding-agent/src/cli/help-extra.ts:68`). For example, a normally installed custom profile can have the new instruction while the default installation is absent or at a different version; plan review then reads a missing or stale definition while the profile’s F2/F3 use its installed definition. This can make acceptance decisions inconsistent, including for security exclusions. The instruction change is reversible, but an improperly admitted release need not be. Change: Resolve the shared section from the active agent directory for every lane, fail closed if it is unavailable, and add controls with different default and active-profile policies and with the default directory absent.
