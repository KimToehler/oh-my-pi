## Blockers

### Correctness (StopCorrectness7)

1. **Correctness: coverage bypasses the blocking threshold** — A specific residual-risk entry can make a non-eligible value-proof blocker offerable, contrary to the gate's prohibition on offering acceptance of threshold-blocking findings. Evidence: design.md:25 makes a missing proof of any material behaviour or failure mode blocking; design.md:45-47 permits an accept, override or freeze whenever every blocker is eligible or covered, and coverage excludes only the enumerated exclusions. specs/review-blocker-disposition/spec.md:124-131 likewise permits an exact-match covered blocker. For example, an F2 reviewer finds that a material failure mode has no discriminating proof, while a reviewed Accepted residual risks entry names that same proof gap and consequence; it need not name a criterion, consumer, security path or other exclusion. The plan therefore permits offering an override even though that blocker breaks the value proof. gate.md:8 explicitly keeps an instruction that offers accepting a blocker the threshold blocks in scope. A deficient proof may then be released; the consequence can be irreversible. Change: Do not let coverage by itself authorize offering a threshold-blocking finding. Reconcile the coverage scenarios and downgrade rules with the gate invariant, including a covered material-proof-gap case.
2. **Correctness: early ask leaves a stale positive verdict usable** — The new stop-before-fix path does not invalidate or replace an earlier current OKAY review when a fresh complete round rejects. Evidence: tasks.md:10 and design.md:33 move the user question into the rejecting round, before fixes and the next review; they do not require recording the REJECT before asking. The existing schema writes review.md only at step 5 after step 4's fix loop (team-config/agent/skills/review-work/openspec/schemas/omp-gated/schema.yaml:387-400), and apply trusts a current OKAY record (schema.yaml:415-420). If a plan already has an OKAY record and is reviewed again without artifact edits, a lens can now reject with an eligible blocker and the user can stop or the session can interrupt at the early ask. The earlier OKAY remains digest-current, so --reviewed can still allow apply despite the newer rejection. Subsequent implementation or release can be irreversible. Change: Before the early ask, durably record the complete rejecting round with its digest and blockers, or otherwise invalidate any prior OKAY without weakening incomplete-round handling; ensure stop or interruption cannot leave apply authorized.
