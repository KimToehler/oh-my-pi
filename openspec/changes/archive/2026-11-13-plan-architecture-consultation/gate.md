# Gate

- **Mandatory class**: concurrency-state
- **Depth**: risky (Mandatory class concurrency-state; the change also alters the plan-review flow and what `--reviewed` accepts)
- **Risk tier**: product
- **Author's risk assessment**: The change adds a state to the existing plan-review flow: a consultation step before a `risky` round, with a retry, a skip-or-stop ask and a resume rule. It therefore keeps the class of a changed state machine. It also changes what `validate-openspec-change.mjs --reviewed`, `--digest` and the merge gate's OpenSpec checks accept for every change, so it is product. What can break: (1) every `risky` change blocked from apply by a validator that rejects valid records, or by a consultation that cannot run (missing model entry, exhausted quota) without a skip path; (2) a `risky` change reaching apply unconsulted because the instruction skips the step without the user; (3) formal reviewers losing independence because a brief or delta patch exposes the consultant's findings; (4) a review digest that ignores a plan edit, so a stale review authorizes apply; (5) Fable's cost repeated because the step re-runs on resume. The worst realistic outcome is apply authorized over unreviewed plan bytes; stale-digest tests on every non-record file guard against it. No credential, wire contract or persisted schema outside the change folder is touched, and the dispatch uses the session's existing provider authentication.
- **Whole-diff review**: not needed (whole-diff surface reviewed in F2)
- **Accepted residual risks**: (1) The author decides each consultation finding without verifier triage (user decision), so a valid finding can be rejected for a weak reason; the record and the formal review are the only checks. (2) `--reviewed` checks the record's form, not that the consultation ran or ran on its pin; the instruction's session-file check enforces the pin, as for `review.md`. (3) Existing installations keep their `models.yml` until it is merged by hand; until then every consultation ends in the user's skip-or-stop ask, and after merging the user can ask for the consultation again. (4) The consultant runs with the repository's context files and rules, unlike the pilot, so this change does not re-measure its quality. (5) No per-dispatch cost cap exists; one consultation costs about $4–8 at list price. (6) A `consultation.md` edited after its review is detected only by the merge gate's `plan_sha256`, not by `--reviewed`.
- **Out of scope for blocking**: plan-mode session plans and the `plan-handoff` high-accuracy review; the generic `oracle` agent and the `oracle` model role; the bundled `plan-reviewer` prompt; measuring whether consultation findings survive the formal review; rollout timing in consumer projects and other branches' open changes (`plan-adopt-and-cap`, `approach-question-resume`, `review-replay-bench`), including their text conflicts in the `review` instruction.
