# Gate

- **Mandatory class**: auth-secrets-pii
- **Depth**: risky (the mandatory class; the change also moves the evidence scan that review-work's QA rows in app repositories rely on)
- **Risk tier**: product
- **Author's risk assessment**: The delivered driver reads real dev passwords of a remote identity provider (onara's Keycloak realm `onara`) from the main checkout's gitignored credentials file and hands them to Maestro, which types them into the real SSO page; that is a real credential crossing a real trust boundary, the reason onara's `kmp-qa-drivers` was `auth-secrets-pii`. The change rewrites where those values come from (configured keys instead of a key pattern, a file found from the working directory instead of the script's directory), so a wrong key list, a wrong root or a lenient configuration parser would leave a value unredacted in console output, a kept Maestro file or committed evidence, or hand the wrong account to a flow. The new no-credentials mode must not let a value exported in the caller's shell reach Maestro unredacted. A broken scan would pass leaking evidence in every repository that uses the driver. The host-wide lock now spans repositories; a wrong lock path would let two repositories' flows drive one device at once. The skill change routes every agent's app QA, so a wrong command or path sends agents back to hand-driving or to a missing script. The change also extends the team rule `ui-automation-credentials` with a condition naming the skill and an evidence section: a condition that does not match leaves a session's first reply free to list evidence before the skill is read, and a broken frontmatter would drop the rule's existing credential guardrails from every session.
- **Whole-diff review**: not needed (whole-diff surface reviewed in F2)
- **Accepted residual risks**: Spectre is pre-1.0 (v0.9.0) with an experimental attach API; preflight admits only 0.9.0 from the sha256-pinned asset. Flow runs on one host are serialized by one lock, and a stale lock is removed by hand. During a run, Maestro's files in the owner-only run root hold the typed values until the sweep; a SIGKILL of the driver leaves them there until the OS clears the temporary directory. The byte scan cannot read screenshot pixels: a custom flow that screenshots the SSO page before its sign-in subflow returns breaks the skill's rule, and such an image would reach the output directory. A configured value of fewer than six bytes is searched in text files and path names only, so a binary file the run keeps that stores such a value verbatim (a database, an archive) is neither swept nor flagged; onara's one such value is account 1's username, and both configured passwords are longer. Until onara's cutover change merges, onara's own driver uses `${TMPDIR}/onara-qa/flow.lock` and the shared driver `${TMPDIR}/app-qa/flow.lock`, so the two exclude each other only through the unlocked-Maestro-run check. A teammate who has not redeployed team config runs the older driver, which refuses a newer schema id but not an older driver's missing fix. A reply that names neither the skill nor another condition of `ui-automation-credentials` gets no evidence rule before its calls run, and a `task` call streamed before the skill-naming call of the same reply can start its subagent under `task.speculativeLaunch` (on by default) before the abort. The rule fires once in every session whose tool call names `app-qa-drivers`, sessions that only edit the skill included, discarding that reply and costing one more model turn.
- **Out of scope for blocking**: onara's cutover (its configuration file, deleting `app_kmp/scripts/qa.mjs`, the onboarding runner's lock path, its repository skill and rule) and weaver's adoption (its configuration, Android test tags as resource ids, its app QA skill), each its own change in its own repository; sign-in subflows and identity-provider page selectors (app repositories); CI execution of flows and physical devices; non-macOS hosts; the sections of the team rule `ui-automation-credentials` other than its frontmatter and `## Evidence you did not write` (unchanged, only relied on). Findings there become follow-ups.
