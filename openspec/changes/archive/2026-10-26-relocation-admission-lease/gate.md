# Gate

- **Mandatory class**: concurrency-state
- **Risk tier**: product
- **Author's risk assessment**: The change adds a cross-session admission barrier between relocations and every peer-message delivery and subagent revival in the process. Realistic failures: a relocation that never releases the barrier (a peer message or a revival hangs forever, an autonomous run stalls), a lease holder that waits for its own admission (deadlock of the move), a barrier scoped too wide (an unrelated ACP session's agents freeze while another relocates), messages reordered or dropped on release, or a barrier scoped too narrow so a turn still starts in the source checkout. The damage is a stalled or silently lost agent conversation, or user work written to the wrong branch; the code runs in every omp session with subagents or IRC, so the tier is product. It is a lock and ordering protocol across sessions, so the class is concurrency-state.
- **Whole-diff review**: needed
- **Accepted residual risks**: A peer that messages a member of a relocating tree waits in its `irc` call until the relocation settles (seconds at most when ACP reloads plugins); this is the chosen delivery semantics (design D1, alternative c), not a defect. A revival that never settles stalls the relocation that waits for it instead of letting it run against a half-revived subagent (design, Risks).
- **Out of scope for blocking**: Client prompts and steering typed into the relocating session itself (human input, which `/move` already refuses while streaming); human prompts sent to an already live subagent through the TUI agent hub chat, RPC `steer_subagent` or a collaboration `chat` (the revival part of those paths is in scope, the prompt that follows on a live session is human input like the previous item); completions of a subagent's own background jobs that wake that subagent (the session-move running-work check counts only the relocating session's own jobs, a pre-existing rule of `session-move-tool` D6); whether `/move` and `/wt` should refuse while subagents run; task resume of a live idle subagent by an agent of another session in the same ACP process (it revives nothing and passes no admission point).
