# Gate

- **Mandatory class**: schema-migration
- **Risk tier**: product
- **Author's risk assessment**: The change alters the merge-gate record, which is the audit trail that keeps unreviewed code out of `main` in every repository deploying team-config. It also widens the set of paths that commits after `reviewed_sha` may touch, so the tier is product, as for review-trailer-repair and plan-review-lenses. The worst realistic failure is fail-open: the new QA exemption admits a file that existed at `reviewed_sha`, or one outside the record's evidence directory. A post-review source change would then merge as reviewed. Less severe is fail-closed: a valid record is refused, for example onara's tracked `docs/evidence` artifacts or a CRLF artifact. That is recoverable by fixing the record, at the cost of a gate round. Class schema-migration: every `qa[]` row of the persisted record gains a required `artifact_sha256` and a tracked-path rule. Records still being written at deploy time must migrate, while merged records stay settled.
- **Whole-diff review**: not needed (one mechanism, the record validator with its tests and fixtures; the other files are guidance text for that same contract)
- **Accepted residual risks**: A post-review commit may add an executable file, such as a `*.test.ts` that a test runner discovers, below the record's evidence directory and cite it as a QA artifact. It is exempt like any other new file there, because nothing in shipped code imports from that directory and the file enters the default branch visibly in the evidence commit.
- **Out of scope for blocking**: Artifacts missing from records already merged into the default branch, which are settled and cannot be restored. Proof that the QA actually ran, the same boundary as for trailers. `gate-convergence.mjs` and the ledger.
