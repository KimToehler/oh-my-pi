# Gate

- **Mandatory class**: wire-contract-api
- **Risk tier**: product
- **Author's risk assessment**: The change alters what external ACP clients (IntelliJ/Air, Zed) get from `session/load`, `session/resume` and `unstable_forkSession`: cases that failed now succeed and run the session in another directory than the request `cwd`. Plausible breakage: a session opened in the wrong directory (tools, rules or extensions of the wrong checkout act on files), a session of another repository opened through a client bound to this one, a relocation that moves or loses a transcript, or a regression of today's same-directory and legacy by-id (#7779) loads. Impact is data-adjacent (transcripts, files the agent edits) and user-visible in every IDE reload, so product tier; the ACP wire is an externally consumed contract, so `wire-contract-api`.
- **Whole-diff review**: needed
- **Accepted residual risks**: ACP v1 and v2 load/resume responses carry no `cwd`, so after a reopen in a worktree the client still shows its project directory while the session runs in the worktree, exactly as after a live `/move` today. A second process may open a relocated session between the relocation's close and the ACP reopen; the existing single-writer lock then moves the ACP copy to a new file, as when two processes resume one session today. Chats that a client already rebound to a fresh session (the three of 2026-10-25) are not restored by this change.
- **Out of scope for blocking**: `session/list` scoping and the TUI picker's worktree aggregation; the UI of the startup picker and the in-session resume selector (their inherited D2 relocation is in scope through the shared helper); `/move`, `/wt`, `session_move` behaviour; an ACP protocol addition for cwd changes; the unarchived `session-move-tool` change folder's own design/gate text about IntelliJ reloads (its gate record binds those files).
