# Gate

- **Mandatory class**: wire-contract-api
- **Risk tier**: product
- **Author's risk assessment**: The change ships to every ACP user and changes the meaning of accepted ACP `elicitation/create` content for every client on v1 and v2: a string select value outside the offered options, or such an item in a multi-select array, now counts as the user's free-text answer. Today it is dropped, which ends a single-question turn as cancelled, shows `(cancelled)` among several questions, or loses a multi-select answer without notice. Clients such as JetBrains Air consume this contract and are released independently, so the class is `wire-contract-api`. The request schema omp sends stays byte-identical, and every response that decoded to a selection before still decodes to the same selection. Plausible breakage: a wrong precedence or join that loses or duplicates typed text; an offered option misread as free text, turning a selection into custom input; a regression in the existing companion-field answers; or a later change to the request shape that breaks Air's `__other` fold. The worst consequence is one wrong or missing answer reaching the model in one turn. No credential, personal data, persisted state or irreversible action is involved, and the transcript records the tool result as before. The tier is `product` because the change ships to users.
- **Whole-diff review**: not needed (the change spans one module, the `askDialog` answer decoding in `packages/coding-agent/src/modes/acp/acp-agent.ts`, plus tests in `acp-agent.test.ts` and `acp-v2.test.ts` and one changelog line; that is below the three independently testable modules that make a whole-diff review needed. The wire-contract class already runs both F2 reviewers)
- **Accepted residual risks**: A client that sends a select value the user did not type, for example a stale default outside the options, now has that value shown to the model as the user's text, where today the turn ends as cancelled. omp cannot tell the two apart on the wire, and the model sees the exact text. No real ACP v2 client is available for F1 (Air speaks v1), so the v2 path is proven by the `acp-v2.test.ts` harness test only, which drives the real `AcpSurfaceV2.elicitForm` over the v2 wire codec.
- **Out of scope for blocking**: the TUI, RPC and collab ask paths (`extension-ui-controller.ts` and the RPC UI context), whose own Other handling is unchanged; `AskTool`'s rule that an empty single-select answer cancels the turn; the extension `select()`, `confirm()`, `input()` and `editor()` elicitations; the upstream PR, a follow-up held until the user decides
