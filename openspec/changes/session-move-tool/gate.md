# Gate

- **Mandatory class**: concurrency-state
- **Risk tier**: product
- **Author's risk assessment**: The change lets the agent change the session's working directory and session-file location mid-run, ending a turn early and starting a continuation. Realistic failures: edits or commands land in the wrong checkout (a mixed-cwd batch, a move while a subagent still writes the old tree), a lost or duplicated continuation (goal continuation plus move continuation), a session file left half-relocated after a failed rescope, or a worktree created outside the repository through path or symlink tricks. The damage is user work written to the wrong branch or an autonomous run that silently stops or runs twice; it ships to every omp user, so the tier is product. The core risk is ordering of turn end, relocation, fences and continuation, which is the concurrency/state-machine class; the tool's approval tier is an existing-mechanism decision, not a new authorization path.
- **Whole-diff review**: needed
- **Accepted residual risks**: In an ACP process hosting several sessions, the relocation's `process.chdir` also changes the process cwd seen by the other sessions, exactly as `/move` does today; tools read `session.cwd`, not `process.cwd()`. LSP servers, MCP servers and persistent eval kernels keep the old workspace after a move, as after `/move`. A JetBrains ACP client that reloads the chat reopens it in its project directory, as documented for `/move`. A concurrent writer that swaps a checked worktree-directory component for an outbound symlink between the `lstat` walk and worktree creation (design D4) is not defended against; Tim accepted this on 2026-10-24 (plan review round 4) because such a race needs a concurrent writer in the repository, which already has more power than this tool. The Verify commands of tasks 7.2 (F3 report first line) and 7.3 (F1 `RESULT` lines) check self-written markers only; Tim accepted this on 2026-10-24 (plan review round 5) because they follow the omp-gated template and the F2 record (`validate-gate-record.mjs`) binds the F3 report by content and requires the QA evidence.
- **Out of scope for blocking**: `/move` and `/wt` behaviour and their existing streaming refusal; relocation of running subagents or a `task` `cwd` parameter; ACP protocol additions for cwd changes; print mode and SDK sessions without a relocator (the tool is absent there by requirement); weaver's `scripts/seed-worktree` and gate-policy changes, which live in that repository.
