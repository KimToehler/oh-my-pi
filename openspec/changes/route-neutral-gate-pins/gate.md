# Gate

- **Mandatory class**: none
- **Depth**: risky (the change alters when plan-review, consultation and F2 merge-gate dispatches count)
- **Risk tier**: product
- **Author's risk assessment**: The change decides which dispatches the plan review, the architecture consultation and the F2 merge gate count, for every member and every gated change. What can break: (1) a check too loose, so a verdict from a substituted model counts (a name rule that matches `claude-opus-5-5` against a `claude-fable-5-2` pin, a lost effort check on `auditor`, or a trailer that names a route its session did not use); (2) a check too strict, so a member's reviews on a direct provider still end INCONCLUSIVE or in the skip-or-stop ask; (3) the instruction texts and the consultation code disagreeing on the rule. Severity is a blocked or a falsely passed merge gate, recoverable by revert, with no data, credential or tenant boundary involved, so class `none`. It stays `product` rather than `internal-tooling` because it changes the team's merge gate, the process boundary that decides what reaches `main`. Pins, seed and agent definitions are unchanged, so no member's route changes.
- **Whole-diff review**: not needed (whole-diff surface reviewed in F2)
- **Accepted residual risks**: (1) Two providers serving different weights under one model name would count as one model; every provider the team uses serves the vendor's model under the vendor's name, and records keep the full `provider/model`. (2) A bare override resolves to whichever authenticated provider carries the exact id; the README recommends provider-prefixed overrides. (3) The two instruction-only checks are model-applied; F1 exercises them in real sessions, but no command enforces them.
- **Out of scope for blocking**: the `measurement-*` experiment agents in `~/.omp/agents/` and the generic `oracle` agent; `validate-gate-record.mjs`'s exact `model_id` against `resolution.model` comparison and its independence labels; runtime model resolution (`resolveModelOverride`, `modelProviderOrder`); the pins themselves and existing members' `config.yml` and `models.yml`; the open branch `feat/consultation-review-hardening` and its text conflicts in `schema.yaml` and `README.md`.
